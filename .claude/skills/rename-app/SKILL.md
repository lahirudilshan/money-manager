# Renaming the app

The app has been renamed once already (money-manager → Dayly,
com.anonymous.moneymanager → com.lahirudilshan.dayly). Two things broke
silently afterwards and this checklist exists so they don't again:

- The shared iCloud shortcut kept calling
  `com.anonymous.moneymanager.SendMessageToDaylyIntent`. The old app was gone,
  so iOS showed the automation as **"turned off"** and no SMS ever arrived.
- `GoogleService-Info.plist` was downloaded for `com.dayly.app`, a bundle id
  the app never shipped under.

First decide **which kind of rename** this is. Each level includes the ones
above it.

| Level | What changes | Cost to users |
|---|---|---|
| A. Display name | What the user reads ("Dayly") | None |
| B. Bundle id / package | `com.lahirudilshan.dayly` | **New app to iOS**: new empty container, so data only comes back by restoring a backup; Shortcuts actions, Firebase and the Google key all have to be redone |
| C. Data names | Drive folder, backup/sync file names, DB file, URL scheme | Old installs and old backups stop being found **unless a legacy fallback is kept** |

Before you start, find every remaining occurrence (run from the repo root):

```
grep -rIn -i -E "com\.lahirudilshan|com\.anonymous|moneymanager|money-manager|dayly" \
  --exclude-dir={node_modules,Pods,.git,build,build-device,.expo,.next,ios} --exclude=yarn.lock .
```

`ios/` is generated by `expo prebuild`, so never edit it. Change the source and
re-run prebuild.

## A. Display name

- `app.json` → `expo.name`. This also names the Xcode project
  (`ios/<Name>.xcodeproj`, `ios/<Name>/`). After changing it, run
  `npx expo prebuild --clean -p ios` and then `pod install` (with
  `LANG=en_US.UTF-8`).
  - `plugins/fix-ios-prebuild.js` finds the project by globbing `*.xcodeproj`,
    and `plugins/withSmsAppIntent.js` uses `getProjectName`. Both follow the
    new name automatically, but check that the Swift intent still lands in
    `ios/<Name>/`.
- `app.json` → `expo.description`. `package.json` and `server/package.json` →
  `name`. `modules/background-work/package.json` → `author`.
- Swift intent `plugins/ios/SendMessageToDaylyIntent.swift`: `title`
  ("Send Message to Dayly") and `description`. **Renaming the struct changes
  the action identifier** (`<bundleId>.<StructName>`) and breaks every
  installed shortcut, so treat that as level B.
- `NSFaceIDUsageDescription` in `app.json`.
- UI copy. Grep for `Dayly` in `app/` and `src/**/components`, e.g.
  `app/(tabs)/settings.tsx` (falls back to `Constants.expoConfig.name`),
  `app/settings/backup.tsx` ("Uploads to your \"Dayly\" folder"),
  `OwnGoogleAiCard.tsx`, `userGemini.ts` error strings, onboarding.
- Docs: `docs/*.md`, `AGENTS.md`, `.claude/skills/*/SKILL.md` (the
  `dayly-ui` skill name).

## B. Bundle id / package

1. `app.json`: `ios.bundleIdentifier`, `android.package`, and
   `ios.infoPlist.BGTaskSchedulerPermittedIdentifiers`
   (`<bundleId>.work.*`). `BackgroundWorkModule.swift` builds
   `"\(bundleId).work.<suffix>"` at runtime, so the plist entry must match it.
2. **Firebase** (`GoogleService-Info.plist`, `app.json` → `extra.firebase`).
   In the Firebase console, register an iOS app with the new bundle id,
   download its plist, and update `extra.firebase.appId`. Check that the
   plist's `BUNDLE_ID` equals the new bundle id.
   - App Check: register the new app and re-add the debug token.
3. **Google OAuth** (Drive backup): the iOS OAuth client
   (`extra.googleClientId`, plus the reversed id in
   `ios.infoPlist.CFBundleURLTypes`) is tied to a bundle id. Create a new iOS
   client for the new id, or edit the existing one, in Google Cloud Console.
   If you change the client id, change both places.
4. **User's own Gemini key** (`src/features/health/services/userGemini.ts`):
   the key is created restricted to `appBundleId()` and sent as
   `X-Ios-Bundle-Identifier`. Update the fallback literal. Users who already
   set a key need it re-created; `readExistingKey` matches by bundle id, so
   it makes a new one.
5. **Shortcuts action (the SMS automation)**. The shared shortcut embeds
   `WFWorkflowActionIdentifier = <bundleId>.SendMessageToDaylyIntent`, so the
   old link is dead after this change.
   - Install the new build on the iPhone, open Shortcuts, rebuild
     **Dayly App Automation** with the new app's "Send Message to …" action,
     share it as an iCloud link, and set it in the catalog DB
     (`UPDATE app_config SET value = '<link>' WHERE key = 'sms_shortcut_url'`).
     Installed apps pick it up without a release. Also update
     `DEFAULT_SHORTCUT_URL` in `src/features/sms/logic/shortcutLink.ts` and the
     link in `docs/sms-intake.md`.
   - To check a link, run this, then download `downloadURL` (replace `${f}`)
     and `plutil -convert xml1` it:
     `curl -s https://www.icloud.com/shortcuts/api/records/<id>`.
     The identifier must start with the new bundle id.
   - Tell existing users to delete the old automation and add the new one.
6. **e2e / scripts**: `e2e/harness.py` (`BUNDLE`), `e2e/pull_device_db.py`
   (`BUNDLE`), and the `exp+<slug>://` scheme in `e2e/journey.py`,
   `e2e/harness.py` and `e2e/cases/test_ledger.py`. The `exp+` scheme comes
   from `expo.slug`.
7. **Data migration**: a new bundle id is a new app with an empty container.
   Nothing moves over by itself. Before installing, take a backup with the
   old build (Drive or file), then restore it in the new one. Say this in the
   release notes.
8. Signing: `DEVELOPMENT_TEAM` and provisioning follow the new id. The first
   device build may need Xcode to register the App ID.

## C. Data names — rename only with a legacy fallback

These strings are what old installs, old backups and the other phone look
for. The pattern that is already in place is **new name for writing, old name
still accepted for reading**. Follow it, and keep the existing legacy names
next to the new one rather than replacing them.

| Thing | Where | Legacy handling today |
|---|---|---|
| Drive folder | `BACKUP_FOLDER_NAME` / `LEGACY_FOLDER_NAME` in `src/features/backup/logic/driveSync.ts`; carried over in `googleDrive.ts` (~L391) | Old folder renamed in place |
| Sync file | `SYNC_FILENAME` / `LEGACY_SYNC_FILENAME` (`driveSync.ts`) | Both read |
| Backup file prefix | `backup.ts` (`dayly-${stamp}.json`, `isSnapshotFilename` regex), `backupFile.ts`, and the `^(dayly\|money-manager)-` regexes in `app/settings/backup.tsx` (x2) and `app/onboarding/welcome.tsx`; `scripts/buildPlanBackup.mjs` | Regex accepts both. **Add the new prefix to every one of these regexes** |
| Multipart boundaries | `dayly-backup-boundary`, `dayly-sync-boundary` | Cosmetic; leave them |
| SQLite file | `DATABASE_NAME` in `src/db/client.ts`; e2e paths `dayly.db` | None. Safe only together with a bundle id change (fresh container). Otherwise add a rename-on-open |
| URL scheme | `app.json` → `scheme` array | Keep `moneymanager` in the list: old Shortcuts still open `moneymanager://sms`. Add the new scheme first, never remove old ones |
| `/sms` route | `app/sms/index.tsx` | Never move (see AGENTS.md) |
| SMS queue folder | `.sms-intake`: `INTENT_QUEUE_DIR` in `smsIntentQueue.ts` **and** `folderName` in the Swift intent | Not app-named; leave it. If changed, change both together |
| Legacy SMS file | `['money-manager', 'sms-inbox.txt']` in `smsInboxFile.ts` | Legacy path; leave it |
| Gemini key display name | `dayly-ai-<tail>` in `src/features/health/logic/userGemini.ts` | Change it only together with the matching logic in `readExistingKey` |

## Verify

1. `yarn typecheck && yarn test`. The backup and driveSync tests pin the file
   and folder names, so update their expectations on purpose and don't just
   regenerate them.
2. Build the bundle and check it compiles (see AGENTS.md → Verifying).
3. `npx expo prebuild --clean -p ios`, then build onto the iPhone and check:
   - Settings shows the new name; Drive backup connects and uploads to the
     expected folder.
   - Restoring a backup made by the **previous** build works.
   - The SMS automation: run the new shortcut once (play → Allow), send a
     test alert, and check that it arrives in Dayly. A missing
     `Documents/.sms-intake` in the container
     (`xcrun devicectl device info files --domain-type appDataContainer --domain-identifier <bundleId>`)
     means the intent never ran.
   - The Health AI features still respond (Firebase App Check under the new
     bundle id).
